任务价值与实际可学习性：根据用户澄清调整推进顺序

时间和资源有限是工作约束。首要目标仍是生产环境中的任务值得学习，正确的官方 DAPO 能利用环境信号改善目标能力。吞吐、内存和运行时优化服务于这个目标；它们本身不构成学习成功。固定随机流的最坏情形证书保留为边界证据，不再作为没有分布支持的主要诊断。

本次只复核已有数据和日志，未新增模型更新、重采样题目或更改奖励、任务生成与训练算法。证据与只读分析脚本见 `research/task_value_learning_20260907`。

可以确定的事实与仍然缺少的证据

1. 官方实现的一个真实更新已通过轨迹、动作掩码、loss、梯度和 Adam 首步核对。曾导致工具 token 进入目标的接口错误已修复。这项执行正确性证据不能证明更新后的解题能力。
2. 修复后的实际记录只有同一道 ATE 的四条更新前轨迹。44 次工具调用包括 27 次有效实验、13 次协议错误及 4 次有效终局答案。错误为：不可操纵目标 5 次、测量中包含干预目标 3 次、未知目标 1 次、预算超支 1 次、效应向量和不为零 3 次。此前临时日志分析按 `type=error` 识别，漏掉实际的 `protocol_error`；已修正分析并用完整事件分解核对。这是分析脚本错误，不是环境协议变更。
3. 四条轨迹的终局质量分别为 0.40428、0.43487、0.43487、0.95531。最后一条输出零向量，消耗全部 65,536 标量观察预算；其余三条分别消耗 1,792、512、640。这道题真值很小，零答案的真实误差确实更低，不能把正确的奖励排序认定为算法错误。也不能把高分或花完预算解释为学会了实验。
4. 现有训练 profile 的默认模式是一次执行审计：没有训练前验证，周期验证关闭。已有 20 道训练题真值已核对，但尚无固定任务上的训练前后能力对照。原 val 仅五题，最优干预只有一致层，不能覆盖该类主要的冲突层。这是当前能力结论的确定证据缺口。
5. 74 道冻结反事实计算题仍有 23 道未认证，是对应真值覆盖的确定缺口。这一冻结压力集的比例不能直接当成生产题库的失败率；尚不能恢复对这些未认证题的信任。它也不要求停止其他已经核对真值的生产任务的学习验证。

已有真实题目的基线对照

以下复用 250 个生产世界、每类 50 道、每题两条采样带的诊断结果。它们已经用于分析，不能再声称是未看过的最终留出集。有限预算解题器只使用合法公开信息；总体观察捷径使用隐藏总体分布作诊断，不能当作可执行解题器。

| 任务 | 固定答案平均质量 | 有限预算启发式平均质量 | 应同时看的任务指标 |
| --- | ---: | ---: | --- |
| ATE | 零向量 0.42936 | 0.59868 | 平均总变差误差 0.04846；零答案 ≥0.9 的有 4/50，≥0.95 的仅 1/50 |
| 反事实区间 | [0,0] 0.39443 | 0.64169 | 平均端点误差 0.11853；零区间 ≥0.9 的为 0/50 |
| 后门调整 | 空集 0.89857 | 0.98786 | 空集合法 12/50；有限策略合法率 89% |
| 最优干预 | state_0 0.61596 | 0.62668 | 固定动作最优率 36%；有限观察最优率 23%，总体观察仅 20% |
| 中介结构 | 空结构 0 | 0.42001 | 完整精确匹配 16%；中介 F1 与边 F1 分别约 0.4447、0.3953 |

ATE 有 10/50 道零答案比总体观察捷径质量更高，但绝大多数题并非零答案接近满分。不能把官方运行的单道弱效应题外推为全库奖励坍缩。后门高质量底座也不等于 DAPO 优势小：在组内标准化中，同题奖励的正仿射变换会抵消，数值 epsilon 除外。

最优干预的观察启发式相对固定 state_0 的配对质量增益为 0.01071，95% 世界级 bootstrap 区间为 [-0.09508, 0.12294]。这一启发式不能解决生产任务要求的强反转，不能据其失败调弱反转条件。相反，需要直接检查模型能否用合法干预获得改变决策的证据。现有这些结果尚未证明一个有限预算因果解题方法在本批冲突任务上稳定优于观察捷径；这是解题机制与学习验证必须共同补齐的缺口。

接下来如何判定进展

- 先复用已冻结任务及解题日志，分析常数答案、观察捷径与合法实验后答案的真实误差差别。特别检查最优干预冲突层中能改变动作排序的信息来自哪项合法实验；不能只测更多观察样本或继续构造罕见弱边。
- 在真值可信的生产任务上做有预算上限的官方 DAPO 验证，必须保存原始基座和更新后模型在相同固定任务上的结果。按家族记录真实误差／合法解率、同题组内答案差异、过滤后实际任务组成和响应截断。诊断子集用于定位问题，不改变训练任务比例或生成律，不冒充全分布泛化证明。
- 如果质量增加而真实误差不改善，检查评分和聚合；如果没有有用的组内答案差异，检查模型实际实验与推断步骤；如果答案产生了有效差异却更新未体现，沿已核对的官方执行路径追踪。一次没有提升不证明 DAPO 不适合，更不能据此换成 RLOO。
- 仍需解决的 CF 联合响应认证、生成条件分布及全图预算校准保留原证明义务。只有与真实失败或可学习性相关的计算瓶颈，才提升为当前优化重点。

资源相关记录的范围

旧训练日志共有 649 个记录组，其中 98 组梯度范数为零；该训练器及检查点已被排除，不能用这些统计诊断当前官方 DAPO。官方 run-02 的生成时间占 95.57%，但使用了全进程 Python 审计，源码明确禁止将它当作速度基准。随后一次纯推理分析在初始化时因 PATH 中找不到 `ninja` 失败，没有形成吞吐测量；原脚本与失败日志仅归档，不继续占据主线。

profile 的 `gen_batch_size` 从 3 改为引用 `train_batch_size`，与已验收 run-02 的 1 组配置一致。固定官方 recipe 会在收集足够非恒定组后截断到训练批大小；默认生成三组而只用一组存在额外丢弃已合格轨迹的路径。这个配置修正避免默认预取盈余，保留动态过滤与官方算法；它不是学习效果的修复，也没有证据表明已验收运行曾使用原默认 3。
