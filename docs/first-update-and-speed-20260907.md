关于用户所问“比之前慢很多”

首步当前总耗时 **1,399.23 秒（23.32 分钟）**。旧长期日志中全部 649 组均值为 517.92 秒（8.63 分钟）；其中相同后门家族的 130 组均值为 **364.42 秒（6.07 分钟）**，中位数 345.35 秒。当前首步约是这个家族旧均值的 **3.84 倍**。排除旧梯度为零的组后，96 组均值为 385.30 秒，仍明显短于当前首步。旧最后 100 步中的 20 个后门组均值为 415.87 秒。此比较使用真实 step_time，不使用恢复训练后带累计步数的 tqdm 表观 ETA。

两边均为每题四条轨迹。旧训练参数元数据记录 `num_generations=4`、`generation_batch_size=4`、`bf16=true`、`model_init_kwargs.dtype=bfloat16`、`vllm_speculative_config=null`、上下文 32,768、prefix caching 开启。不能把这次变慢说成批次扩大、旧版使用 MTP 或旧版必然量化而新版未量化。

本次 1,271.57 秒（90.88%）在生成，42.60 秒重算旧策略概率，75.22 秒更新 actor，6.68 秒同步权重。四条轨迹的环境工具调用平均累计仅 0.484 秒、最大 1.017 秒；该数字是工具调用段累计计时，不含排队与模型生成。因此当前组的主要耗时在模型推理路径，不能归因于这道题的 CPT／后门计算核。不同反事实任务的生成核仍须分别看记录。

已经确认的执行路径差别

1. 当前训练 profile 显式设置 `enforce_eager=true`。当前 vLLM 源码明确据此禁用 `torch.compile` 和 CUDA Graph。它是当前配置的具体效率代价，不是标准 DAPO 的必要条件。接入时保留这个保守配置，并未完成与旧推理优化的等价恢复，需要在正确性条件下继续验收。
2. 保留的旧 TRL 推理同步源码调用 `model.merge_adapter()`，将合并后的权重推送给 vLLM，再对训练侧 unmerge；当前官方路径为运行时 LoRA，实际日志出现 LoRA shrink/expand 内核，官方 server 配置 `enable_lora=true`。运行时 LoRA增加额外算子，合并方式也有同步成本与 BF16 舍入差异，不能直接跳过概率／更新核对切换。
3. 旧推理启动代码没有强制 eager；现存旧环境的默认值是 false。但没有从这份旧训练日志获得每个阶段实际 CUDA Graph 命中的记录，因此源码默认仅能支持执行配置对照，不能精确给出历史 CUDA Graph 节省了多少秒。
4. 新训练从原始基座开始，旧记录来自历史适配器，不是相同策略和相同世界。首步还包含部分首次内核编译。当前组工具动作平均 23.5 次，旧后门家族平均 23.03 次，不能仅以工具调用次数解释 3.84 倍差别。

目前不能把 3.84 倍定量归因于其中某一项。旧 `completions/mean_length` 只计模型生成 token（源码按 `tool_mask` 求和），当前 `response_length/mean` 按 response attention mask 计数，包含工具文本。把旧 5,162.76 与新 12,027.25 直接相除来声称输出变长 2.33 倍是错误的。未做同权重、同提示、同生成长度的受控计时，也不能把首步线性外推为 10,000 步的准确完工日期。

下一项效率验收应沿官方推理配置处理编译／CUDA Graph 和 LoRA 执行方式：在不改变任务、奖励、采样概率语义及 DAPO 损失的前提下，比较相同输入的执行成本，并复核动作掩码、采样概率、重要性权重和实际更新。当前运行继续，未在运行中改写配置或启动竞争 GPU 任务。用户要求的最终 10,000 次更新仍在完整 goal 中，取消更小步数截断及会提前停止最终运行的墙钟上限；当前验证不是最终训练。

证据入口

`research/training_submission_20260907/first-update.tar.gz` 保存首次更新日志、官方 rollout 原文、原始环境事件及快照分析；哈希在 `first-update.sha256.json`。`compare_speed.py` 重放旧日志与新快照的时间统计，结果为 `speed-comparison.json`。旧日志及哈希已经归档于 `research/task_value_learning_20260907`。

`capture_progress.py` 是只读分析器，不接入运行中的模型。当前官方 dump 不含 request_id，因此它按完整 JSON 命令序列唯一匹配原始事件，不能仅按奖励或行号猜测对应。官方 dump 的 `score` 被同名原始分数元数据覆盖；分析使用记录的 `raw_reward + overlong_reward` 还原 shaping 后奖励，不能把 dump 的 score 列误当成实际训练奖励。工具事件和日志快照可能包含下一组尚未完成的记录，未完成记录不计作错误或能力分母。
